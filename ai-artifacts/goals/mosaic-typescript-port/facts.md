# Facts

Approved through Plannotator. Verification choices are recorded in [Fact metadata](./facts.meta.json).

- `fact-01`: The finished application uses TypeScript, Bun, and Effect, and has no Python runtime dependency or Python fallback.
- `fact-02`: CI runs strict TypeScript checking, Oxlint, and vendored anti-slop generic and Effect rules. Tool versions and anti-slop provenance are pinned, and the no-module-mocking policy covers Bun as well as other test APIs.
- `fact-03`: The Python compatibility reference is revision 8b7bb76cf88e9be0452f126209aa58f84be0b0ed, manifest version 0.5.0. Commands, aliases, action IDs, hooks, popup entrypoints, environment inputs, and exit behavior remain compatible.
- `fact-04`: The parity inventory covers every reference capability, including colors, labels, themes, sidebar metadata, agent tracking and views, interactive panes, agent pruning, pane operations, installation, migration, recovery, maintenance commands, and refresh scheduling.
- `fact-05`: Configuration edits remain surgical, validate candidates against baseline diagnostics, retain backups, detect ownership conflicts, and use atomic writes. Invalid candidates leave the configuration file unchanged.
- `fact-06`: Uninstall restores owned configuration to its recorded prior state, including absence and exact bytes where restoration promises them. User edits and pre-existing keybindings survive according to the reference conflict and explicit-force behavior.
- `fact-07`: Migration preserves complete Window Manager state and restoration records without overwriting existing Mosaic data. Older Chromatic imports never apply stale sidebar_backup, theme_backup, or last_written records. Source data remains available for rollback.
- `fact-08`: The TypeScript application reads existing settings and state without unapproved compatibility tightening. The frozen Python reference can read TypeScript-written state and use its restoration records during an isolated rollback test.
- `fact-09`: Mutating operations retain the shared cross-process lock semantics. Contention, interruption, and process death are tested on macOS and Linux, including worker ownership locks.
- `fact-10`: Mosaic preserves metadata ownership, leaves themed_model_tier untouched, preserves rows_by_agent, and respects sidebar token limits. Titles have no TTL, and elapsed metadata retains the 30-second refresh and 45-second TTL contract.
- `fact-11`: Short-lived commands and one effective refresh publisher per socket generation remain the process model. Reconciliation does not create duplicate publishers, restart restores publication, and workers stop when their ownership or registration ends.
- `fact-12`: Agent pruning requires confirmation, preserves protected agents, and rechecks liveness and eligibility immediately before closure. An agent that becomes ineligible after selection is not closed.
- `fact-13`: Pane moves, promotion, layout cycling, equalization, and resizing preserve reference behavior. Partial failures preserve recoverable panes and report incomplete recovery instead of silently losing panes.

- `fact-18`: Picker, board, pruner, and pane-move workflows have scripted pseudo-terminal tests for applicable navigation, confirmation, cancellation, resizing, exit behavior, and terminal restoration.
- `fact-19`: The compiled release artifact and manifest launch commands work under minimal PATH and unrelated working directories. They do not require a separate Python runtime and do not inherit unintended .env or bunfig.toml behavior.
